    PageRank in depth

    Power iteration

    Start from any distribution and apply one random-surfer step to all nodes at once, over and over. The error shrinks by a factor of about α per pass, and each pass reads every link exactly once.

    Power iteration is the simplest way to compute PageRank and most other spectral rankings. Start with a guess, typically the uniform distribution. Apply the PageRank equation’s right-hand side to get a new vector. Repeat until the vector stops changing. Each pass costs one scan over all arcs. The method is old, it is slow compared with more sophisticated solvers, and it has computed more rankings than any other algorithm because it is easy to implement, parallelise and reason about.

    The algorithm

    p = [1/n] * n
repeat:
    D = sum of p[u] over dangling nodes u
    q = [(1 - α + α·D) / n] * n            # teleport and dangling mass
    for each arc u → v:
        q[v] += α · p[u] / outdeg[u]
    change = sum |q - p|
    p = q
until change < ε

    The loop over arcs is the whole cost. On a graph with mmm arcs and nnn nodes, one pass is O(n+m)O(n + m)O(n+m) time with two vectors of nnn entries in memory. The order in which arcs are visited does not change the result, which makes the pass easy to split across threads or machines.

    Why it converges

    One pass computes pk+1=pkGp_{k+1} = p_k Gpk+1​=pk​G, where GGG is the PageRank matrix: the row-stochastic matrix combining links, dangling jumps and teleportation. GGG has largest eigenvalue 1 with the PageRank vector as its eigenvector (see Perron–Frobenius). Writing the error in terms of GGG’s other eigenvectors, each pass multiplies the component along eigenvector iii by λi\lambda_iλi​, so the error decays like ∣λ2∣k|\lambda_2|^k∣λ2​∣k, where λ2\lambda_2λ2​ is the second-largest eigenvalue in modulus. Haveliwala and Kamvar showed that ∣λ2∣≤α|\lambda_2| \le \alpha∣λ2​∣≤α for the PageRank matrix. A direct argument bounds every pass, not only the long run: the error sums to zero, so the teleport term cancels and one pass shrinks the error’s L1 norm by at least a factor α\alphaα. The starting error is at most 2, so

    ∥pk−p∥1≤2αk.\| p_k - p \|_1 \le 2\alpha^k .∥pk​−p∥1​≤2αk.

    With α=0.85\alpha = 0.85α=0.85, every 14 passes gain about one decimal digit. The bound does not depend on nnn: a graph with 7 nodes and a graph with 120 million nodes need about the same number of passes for the same precision.

    When to stop

    The change between passes is easy to measure, but it is not the error. For PageRank the two are related by

    ∥pk−p∥1≤α1−α ∥pk−pk−1∥1,\| p_k - p \|_1 \le \frac{\alpha}{1 - \alpha}\, \| p_k - p_{k-1} \|_1 ,∥pk​−p∥1​≤1−αα​∥pk​−pk−1​∥1​,

    so with α=0.85\alpha = 0.85α=0.85 the true error can be 5.7 times the observed change. Common choices:

    • A fixed tolerance on the L1 change, often 10−610^{-6}10−6 to 10−1010^{-10}10−10. The L1 norm sums errors over all nodes, so a tolerance of 10−610^{-6}10−6 bounds the total error but still lets a single node be off by more than 100 times the average score 1/n1/n1/n on a 120-million-node graph. If the order of low-ranked nodes matters, use a much smaller tolerance or check the relative change of each node.
    • Rank stability. Stop when the top kkk positions have not changed for several passes. Rankings converge much faster than values.
    • A fixed number of passes. The original TrustRank paper used 20. With α=0.85\alpha = 0.85α=0.85, 50 passes bound the L1 error by 2×0.8550≈6×10−42 \times 0.85^{50} \approx 6 \times 10^{-4}2×0.8550≈6×10−4.

    Speeding it up

    • Gauss–Seidel uses each updated score immediately within the same pass, typically halving the number of passes. Common Crawl uses a parallel Gauss–Seidel solver (see PageRank as a linear system).
    • Extrapolation. Kamvar, Haveliwala, Manning and Golub estimated and subtracted the slowest-decaying error components from a few successive iterates, cutting passes substantially on web graphs.
    • Adaptive iteration. Most nodes converge in a few passes while a minority take many. Skipping nodes whose scores have stopped changing saves work.
    • Block structure. Most links stay within a host. Computing local PageRank within each host first and combining the blocks gives a good starting vector (BlockRank).
    • Local and sampling methods avoid global passes entirely when only some scores are needed (see push algorithms and Monte Carlo PageRank).

    Pull or push

    The loop above pushes: it reads each node’s out-links and adds to its targets. The pull form reads each node’s in-links from the transposed graph and sums contributions into one entry at a time. Pull needs the transpose but writes each entry once, so parallel threads never conflict; push needs only the forward graph but parallel writes to the same target must be synchronised. Large-scale implementations, including LAW’s, use the transposed graph and pull. PageRank at scale covers the memory and bandwidth arithmetic.

    Beyond PageRank

    The same loop computes eigenvector centrality (without teleport, normalising each pass), Katz centrality and HITS (alternating two products). None of them enjoys PageRank’s guarantee: their convergence rate depends on the graph’s own eigenvalue gap, which can be tiny, and periodic graphs can make the iterates oscillate forever. The teleport term is what makes PageRank’s power iteration reliably fast.
