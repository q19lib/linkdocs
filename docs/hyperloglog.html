    Computing at scale

    HyperLogLog

    A counter that estimates how many distinct items it has seen, within a few percent, using a few bytes. Its counters merge by taking maxima, which is what lets HyperBall count reachable nodes for a hundred million nodes at once.

    How many distinct domains link to a site? How many nodes lie within three links of a node? Counting distinct items exactly requires remembering every item seen, which for a hundred million nodes, each needing its own count, is far too much memory. HyperLogLog (HLL), published by Philippe Flajolet, Éric Fusy, Olivier Gandouet and Frédéric Meunier in 2007, estimates the number of distinct items with a relative error around 1.04/m1.04/\sqrt{m}1.04/m​ using mmm tiny registers, and two counters can be merged into a counter for the union of their sets with a register-by-register maximum. That merge is what makes approximate harmonic centrality computable on web-scale graphs (see HyperBall).

    The idea

    Hash each item to a long string of random-looking bits. In a uniformly random bit string, the first 1 appears at position 1 with probability ½, at position 2 with probability ¼, and at position kkk with probability 2−k2^{-k}2−k. If you have seen NNN distinct items, the largest such position among their hashes is likely to be around log⁡2N\log_2 Nlog2​N. Remember only that maximum, a number below 64 that fits in 6 bits, and you have a rough estimate of NNN: 2max⁡2^{\max}2max. Duplicates do not matter, because the same item always hashes to the same string.

    One maximum is a very noisy estimate. HyperLogLog splits the stream: the first bbb bits of each hash choose one of m=2bm = 2^bm=2b registers, and each register keeps the maximum first-1 position of the items routed to it. The estimate combines all registers with a harmonic mean, which tames the outliers:

    E=αm m2(∑j=1m2−Mj)−1,E = \alpha_m\, m^2 \left( \sum_{j=1}^{m} 2^{-M_j} \right)^{-1},E=αm​m2(j=1∑m​2−Mj​)−1,

    where MjM_jMj​ is register jjj’s maximum and αm\alpha_mαm​ a bias-correcting constant (about 0.7213 for large mmm). The standard error is about 1.04/m1.04 / \sqrt{m}1.04/m​.

    Accuracy against memory

    Registers mmm Memory at 6 bits each Typical relative error
    16 12 bytes 26%
    128 96 bytes 9.2%
    1,024 768 bytes 3.3%
    16,384 12 KB 0.8%

    The memory does not depend on how many items are counted: 12 KB estimates a billion distinct items as well as a million. The error does not shrink with more data, only with more registers.

    Merging counters

    Two HLL counters built with the same hash function and the same mmm merge by taking, for each register, the larger of the two values. The result is exactly the counter that would have been built from the union of the two streams. This cheap union is the property that graph algorithms exploit: the set of nodes within distance t+1t + 1t+1 of xxx is the union of xxx’s own ball and the balls of its neighbours, so one round of register-wise maxima over all arcs grows every node’s ball by one step.

    Intersections are not so easy. Estimating the overlap of two sets from their HLL counters, by inclusion–exclusion, has large errors when the overlap is small relative to the sets.

    Practical refinements

    • Small cardinalities. When many registers are still empty, the raw estimate is biased; the original paper switches to linear counting, mln⁡(m/V)m \ln(m / V)mln(m/V) with VVV empty registers.
    • HyperLogLog++. Heule, Nunkesser and Hall at Google used 64-bit hashes to avoid collisions at large cardinalities, an empirical bias correction for the mid range, and a sparse representation for small counts. Most production systems implement this variant.
    • Hash quality. The analysis assumes the hash behaves like a random function. A weak hash on structured inputs, such as sequential integer node ids, can bias every counter the same way.

    Uses in link analysis

    • Neighbourhood functions and centralities. HyperBall keeps one HLL counter per node and computes, for every node, how many nodes lie within each distance. From those counts come harmonic centrality, closeness, the neighbourhood function and the effective diameter of graphs with billions of arcs.
    • Distinct referring domains. Counting the distinct domains that link to each site over a stream of crawled links is a cardinality problem per target; HLL counters answer it in a fixed small memory per site.
    • Deduplication statistics. Estimating how many distinct URLs, hosts or pages a crawl has seen.

    The approximation leaves traces. In Common Crawl’s 2026 domain ranks, computed with HyperBall, 293 domains with at least one in-link have harmonic value 0: for those domains the counters failed to register a single arrival, which happens when the newcomer’s hash lands in a register that already holds an equal or larger value. Treat HLL-based values as estimates with a known relative error, not as exact counts.
