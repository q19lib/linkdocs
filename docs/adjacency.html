    Adjacency matrices and lists

    Two ways to write a graph down. The matrix suits the algebra behind every spectral ranking; compressed lists are how a real web graph fits in memory.

    A graph needs a concrete representation before a program can rank it. The adjacency matrix writes it as a table of zeros and ones, which makes linear algebra available: PageRank, eigenvector centrality, Katz centrality and HITS are all statements about this matrix. The adjacency list stores, for each node, only the nodes it links to, which is the only form that fits a web graph in memory. Every serious implementation thinks in matrices and computes with lists.

    The adjacency matrix

    Number the nodes 000 to n−1n - 1n−1. The adjacency matrix AAA is the n×nn \times nn×n matrix with

    What the algebra buys

    Matrix products answer graph questions directly:

    • Degrees. With 1\mathbf{1}1 the all-ones vector, A1A\mathbf{1}A1 gives every out-degree and A⊤1A^\top\mathbf{1}A⊤1 every in-degree (see degree).
    • Walks. (Ak)uv(A^k)_{uv}(Ak)uv​ counts the walks of exactly kkk steps from uuu to vvv. In the example, (A2)E,A=2(A^2)_{\text{E},\text{A}} = 2(A2)E,A​=2: E reaches A through D and through C. Katz centrality sums these counts over all kkk with decaying weights.
    • Transition probabilities. Divide each non-empty row by its sum to get the matrix PPP with Puv=1/d+(u)P_{uv} = 1/d^+(u)Puv​=1/d+(u) for each link. Row uuu of PPP is the probability distribution of a random walk that leaves uuu along a random out-link. PageRank is the long-run distribution of a walk on a repaired version of PPP.
    • Spectral rankings. eigenvector centrality is the dominant eigenvector of A⊤A^\topA⊤, and HITS uses the dominant eigenvectors of A⊤AA^\top AA⊤A and AA⊤A A^\topAA⊤.

    Why nobody stores the matrix

    A dense matrix needs n2n^2n2 entries. For Common Crawl’s domain graph, n=119,722,885n = 119{,}722{,}885n=119,722,885, so even one bit per entry takes 1.43×10161.43 \times 10^{16}1.43×1016 bits, about 1.8 petabytes. Yet only 2,450,405,793 entries are ones: 0.000017% of the matrix. Web graphs are extremely sparse, with an average of 20 links per node however large nnn grows. Storage must scale with the number of arcs mmm, not with n2n^2n2.

    Adjacency lists and CSR

    An adjacency list stores each node’s out-neighbours. The compact way to do this is compressed sparse row (CSR): one array holding every node’s successors back to back, sorted by source, and an offsets array marking where each node’s run begins.

    For the running example (A = 0, …, G = 6):

    offsets: 0  2  3  5  7  10  10  10        node u's successors are targets[offsets[u] .. offsets[u+1])
targets: 1 2 | 2 | 0 6 | 0 2 | 2 3 5

    Node E (index 4) owns targets[7..10) = 2, 3, 5, that is C, D and F. F and G own empty runs, so their offsets repeat.

    The costs are easy to state:

    Structure Size At Common Crawl’s scale
    Offsets, 32-bit 4(n+1)4(n + 1)4(n+1) bytes 479 MB
    Targets, 32-bit 4m4m4m bytes 9.8 GB
    Same again for in-links (the transpose) 10.3 GB

    The offsets fit in 32 bits only because 2.45 billion arcs is below 2322^{32}232; a page-level graph with tens of billions of arcs needs 64-bit offsets.

    CSR makes the inner loop of PageRank a straight scan. A “pull” iteration walks each node’s in-links in the transposed graph and sums contributions, reading the targets array once from start to end. Sequential reads of the arc array cost little; the random reads of score vectors cost the most (see PageRank at scale).

    Compressed lists

    Sorted successor lists have structure that CSR ignores. Neighbouring nodes in a well-chosen order link to similar targets, and consecutive targets differ by small gaps. The WebGraph framework exploits both and stores Common Crawl’s domain graph in 15.1 bits per arc, 4.6 GB instead of 9.8 GB for the targets alone, while still decoding a node’s successors quickly. How well this works depends on the order of the nodes; see node orderings.

    The transpose

    Many measures look at in-links: harmonic centrality needs distances to a node, and pull-style PageRank sums over in-links. Both use the transposed graph A⊤A^\topA⊤, which reverses every arc. Common Crawl ships its graph in both directions for this reason: domain.graph holds out-links and domain-t.graph holds in-links, 4.6 GB each.
